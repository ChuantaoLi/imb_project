# SMOM 中 $x_i.N_{k_2}$ 的用途详解

> **来源论文**: *Synthetic Minority Oversampling Technique for Multiclass Imbalance Problems*
> Tuanfei Zhu, Yaping Lin, Yonghe Liu. Pattern Recognition 72 (2017) 327–340.

---

## 一句话概述

$x_i.N_{k_2}$ 是 $x_i$ 在**跨所有类别**的样本空间中寻找的 $k_2$ 个最近邻集合，专供 **NBDOS 聚类算法**使用，用于判断 $x_i$ 处于类 $c$ 主导的"安全区"还是被其他类包围的"边界区"，从而将类 $c$ 的所有实例划分为**优良实例（$Oi_c$）** 与**困境实例（$Ti_c$）**。

---

## $x_i.N_{k_2}$ 的计算方式

在 Algorithm 1 的第 2.3 步：

> 在 $x_i.N_{k_3}^{c} \cup x_i.N_{k_3}^{\tilde{c}}$ 的并集中找到 $x_i$ 的 $k_2$ 个最近邻集合，记为 $x_i.N_{k_2}$。

其中：

- $x_i.N_{k_3}^{c}$：$x_i$ 在类 $c$ 内部的 $k_3$ 个最近邻（$k_3 = \max\{k_1, k_2\}$）
- $x_i.N_{k_3}^{\tilde{c}}$：$x_i$ 在其他所有类别中的 $k_3$ 个最近邻

因此 $x_i.N_{k_2}$ **同时包含类 $c$ 的实例和其他类别的实例**，是对 $x_i$ 局部邻域的一个跨类别快照。

---

## 为什么需要 $x_i.N_{k_2}$？——与 $x_i.N_{k_1}^c$ 的对比

Algorithm 1 中实际维护了**两个不同用途的近邻集合**：

| 近邻集合 | 搜索范围 | 大小 | 核心用途 | 类比 |
|----------|----------|------|----------|------|
| $x_i.N_{k_1}^c$ | **仅类 $c$ 内部** | $k_1$ | 生成合成样本的**候选方向池**（Step 5, 6, 8） | "往哪里生成" |
| $x_i.N_{k_2}$ | **跨所有类别** | $k_2$ | NBDOS 聚类的**局部密度依据**（Step 3） | "这里安不安全" |

### 为什么 $x_i.N_{k_1}^c$ 不够用？

如果只用 $x_i.N_{k_1}^c$（仅类 $c$ 内部近邻），NBDOS 看到的将是这样的画面：

> $x_i$ 附近有 5 个类 $c$ 的邻居 → 看起来很安全 → 标记为优良实例。

但实际上，在同样的局部区域内，可能还有 **10 个其他类别的实例**离 $x_i$ 更近，只是它们不在 $x_i.N_{k_1}^c$ 中而已。$x_i$ 实际处于多类混杂的边界地带，是一个困境实例。

**因此必须用跨类别的 $x_i.N_{k_2}$ 来暴露真实的局部类分布情况。**

---

## 用途一：判定软核心实例（Soft Core Instance）

NBDOS（Algorithm 2, 第 3–6 行）利用 $x_i.N_{k_2}$ 判断 $x_i$ 是否为软核心实例：

```
for all xi ∈ Sc do
    Tem = { xj ∈ xi.Nk2 | xj 的类别为 c }
    if round(|Tem| / k2) >= rTh then
        xi is a soft core instance
```

### 判定逻辑

$$
\text{软核心实例} \iff \frac{|\{x_j \in x_i.N_{k_2} \mid class(x_j) = c\}|}{k_2} \geq r_{Th}
$$

即：在 $x_i$ 的 $k_2$ 个跨类近邻中，**类 $c$ 实例所占的比例**达到阈值 $r_{Th}$ 时，$x_i$ 被认定为软核心实例。

### 直观含义

- $r_{Th}$ 通常设得较高（如 $0.6 \sim 0.8$），意味着软核心实例是那些**局部区域以类 $c$ 为主导**的实例。
- 软核心实例是聚类扩展的"种子点"——它们所在的区域被认为是类 $c$ 的安全主导区。
- 非软核心实例（周边类 $c$ 比例不足）自然不会成为种子的来源，它们的聚类标签将保持为 $0$（即默认归入困境实例）。

---

## 用途二：构建 $G_k^c$-邻域

NBDOS（Algorithm 2, 第 10–13 行）对每个软核心实例 $x_i$ 构建其 $G_k^c$-邻域：

```
for all xi ∈ sfSc do
    Tem = { xj | xi ∈ xj.Nk2 }  // xi 的逆 k 近邻
    Hkc(xi) = Hkc(xi) ∪ (Tem ∩ sfSc)
```

### $G_k^c$-邻域的构成

$$
G_k^c(x_i) = \underbrace{\{x_i\}}_{\text{自身}} \cup \underbrace{\{x_j \in x_i.N_{k_2} \mid class(x_j) = c\}}_{\text{k近邻中的同类别实例}} \cup \underbrace{\{x_j \in x_i.RN_{k_2} \mid x_j \text{ 是软核心实例}\}}_{\text{逆k近邻中的软核心实例}}
$$

其中 $RN_{k_2}$ 表示逆 $k$ 近邻（reverse $k$-nearest neighbors），即那些以 $x_i$ 为其 $k_2$ 近邻之一的实例。

### 为什么这样设计？

1. **包含自身** — 保证自反性：$x_i \in G_k^c(x_i)$。
2. **包含 $k$ 近邻中的同类别实例** — 将邻域内本就属于类 $c$ 的实例拉入聚类，这是密度连接的直接体现。
3. **包含逆 $k$ 近邻中的软核心实例** — 保证**对称性**（Lemma 1 证明），即 $x_j \in G_k^c(x_i) \implies x_i \in G_k^c(x_j)$。这是聚类能够沿类 $c$ 主导区域自然扩展的关键。

### 关键约束

注意到第 3 类成分中只纳入**软核心**实例。这意味着 $G_k^c$-邻域的扩展只会经过那些本身也处于类 $c$ 主导区域的实例，**不会通过困境实例向外连接**，从而确保：

> 聚类结果中的每个实例都确实位于类 $c$ 的真实主导区域，而非偶然靠近某个软核心实例的边界点。

---

## 用途三：聚类扩展（expandCluster）

NBDOS 的 `expandCluster` 函数（Algorithm 2, 第 26–41 行）利用 $G_k^c$-邻域进行类似 DBSCAN 的密度扩展：

```
function expandCluster(sfSc, xi, curId, Sc.cl)
    sfC = {xi}
    xi.cl = curId
    while sfC ≠ ∅ do
        xj = draw out an instance from sfC
        for all xl ∈ Hkc(xj) do
            if xl.cl = 0 then
                xl.cl = curId          // 归入当前聚类
                if xl ∈ sfSc then
                    sfC = sfC ∪ {xl}   // 如为软核心，继续扩展
        sfC = sfC \ {xj}
    return Sc.cl
```

### 扩展过程的含义

从种子软核心实例 $x_i$ 出发：

1. 将 $G_k^c(x_i)$ 中所有未标记实例归入当前聚类；
2. 对其中的软核心实例，继续以它们的 $G_k^c$-邻域向外扩展；
3. 重复直到 $sfC$ 为空（即当前聚类的边界不再包含任何软核心实例）。

这个过程能够发现**任意形状**的类 $c$ 主导区域，因为 $G_k^c$-邻域沿着密度可达的软核心实例链自然蔓延，不受球状假设的限制。

---

## 从 $x_i.N_{k_2}$ 到最终分类的完整链路

```
x_i.N_{k_2}（跨类别近邻）
        │
        ▼
┌───────────────────────────────┐
│  用途①：判定软核心实例          │
│  |c类实例| / k_2 >= r_Th ?     │
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  用途②：构建 G_k^c-邻域        │
│  自身 + k近邻c类 + 逆k近邻软核心│
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  用途③：expandCluster 密度扩展 │
│  沿 G_k^c-邻域链逐层扩展        │
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  丢弃成员数 < n_Th 的小聚类     │
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  聚类标签 ≠ 0 → Oi_c（优良实例）│
│  聚类标签  = 0 → Ti_c（困境实例）│
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  Oi_c: 均匀随机选择近邻方向     │
│  Ti_c: 加权选择近邻方向         │
│  → 生成合成样本                 │
└───────────────────────────────┘
```

## 总结

$x_i.N_{k_2}$ 的跨类别特性使其成为 NBDOS 聚类算法**感知局部多类分布**的唯一输入，承担三个递进的功能：

| 用途 | 位置 | 功能 |
|------|------|------|
| 判定软核心实例 | NBDOS 第 3-6 行 | 以 $k_2$ 近邻中类 $c$ 的比例 $\geq r_{Th}$ 为标准，筛选聚类的"种子点" |
| 构建 $G_k^c$-邻域 | NBDOS 第 10-13 行 | 以 $k_2$ 近邻和逆 $k_2$ 近邻为基础，建立对称且自反的邻域关系 |
| 驱动密度扩展 | NBDOS expandCluster | 沿 $G_k^c$-邻域链发现任意形状的类 $c$ 主导聚类 |

最终结果是：**位于类 $c$ 安全主导区的实例无需计算选择权重（节省计算量），位于边界地带的困境实例则进入方向选择的加权流程（避免过度泛化）**。
